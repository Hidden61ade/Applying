# 2026-05-23 — Day 4: custom domain

Site is now live at **hidden61ade.com** with HTTPS.

## What's in

- Registered `hidden61ade.com` on Bluehost.
- GitHub Pages custom domain configured to `hidden61ade.com`.
- `public/CNAME` and `astro.config.mjs` updated to `hidden61ade.com`.

## DNS war log

The path to a working domain was longer than expected.

1. **Wrong control panel.** Spent an hour editing DNS records in Bluehost's Zone Editor — completely useless. The domain's actual nameservers are Cloudflare (`seamus.ns.cloudflare.com` / `eve.ns.cloudflare.com`). Bluehost hosts the registrar and the shared-hosting account, but Cloudflare is authoritative. Changes in Bluehost cPanel propagate to NS1/NS2.BLUEHOST.COM, which the internet simply does not consult.

2. **Stale A record.** Cloudflare had a leftover `@` A record pointing to `50.6.42.70` (Bluehost shared hosting) alongside the four GitHub Pages IPs. Also a `www` A record at the same Bluehost IP. Both needed deleting.

3. **Cloudflare proxy (orange cloud) breaks GitHub Pages verification.** The four GitHub Pages A records were added with Cloudflare proxy enabled. GitHub's DNS check resolves the domain and expects to see `185.199.x.x`; instead it saw Cloudflare's anycast IPs and returned `NotServedByPagesError`. Fixed by switching all four records to **DNS only** (grey cloud).

4. **Final Cloudflare zone** that worked:
   - `@` A → `185.199.108–111.153` × 4, DNS only
   - `www` CNAME → `hidden61ade.github.io`, DNS only
   - No other A records on the root.

Cloudflare propagation was near-instant after saving. GitHub DNS check passed within seconds.

## Decisions

- Keep Cloudflare as DNS provider (already managing the domain), not Bluehost Zone Editor.
- All GitHub Pages records must be **DNS only** — Cloudflare proxy breaks GitHub's domain verification and SSL provisioning.
- `www` uses a CNAME directly to `hidden61ade.github.io` rather than chaining through the apex.

## What worked / didn't

- ❌ Bluehost Zone Editor — changes go to Bluehost NS, ignored by the internet.
- ❌ Cloudflare proxy on GitHub Pages A records — verification always fails.
- ❌ Waiting for Bluehost's NS2 to sync before diagnosing — cost ~1 hour.
- ✅ `Resolve-DnsName -Server NS1.BLUEHOST.COM` to check authoritative records directly.
- ✅ `Resolve-DnsName -Type NS -Server 8.8.8.8` to discover the real authoritative NS (Cloudflare).
- ✅ Cloudflare DNS propagates in seconds — no waiting after changes.
